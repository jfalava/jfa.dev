### The header — User button

The top bar always has a round **User** icon on the right. It opens the `/user` settings page, where you can manage your name, connected browsers, passkeys, and local data. The publish prompt has a separate compact dialog for choosing a name or connecting another device. The app header and the docs site header look similar but are separate — the app shows KEWEKE navigation, the docs site shows Docs navigation — so the drop-down menus never mix.

- If you are anonymous, the page reminds you to create a name.
- If you have a name, the page shows your current name and identity controls.

### Settings — /user

<UserSettingsPreview variant="remote" />

The `/user` page has a header with your avatar and a label:

- **Anonymous** / **Local user** / **Remote user** — tells you which state your browser is in.
- Your display name — or “Anonymous” if you have not set one.
- A table of settings that adapts to your state: it only shows rows that make sense for you (for example, “approve a browser” and “manage devices” only for remote users).

### The dialog you just used

The identity dialog opened from the publish prompt contains only the steps needed to choose a name or connect another device without leaving the list you were viewing. The `/user` page contains the full settings table.

### The shopping list — signed badge

Each row in the shopping list ends with a small badge that tells you who last touched that item.

<SignedBadgePreview />

- **Unsigned** — the item was created before the naming system existed or the author is unknown.
- **Added by …** — plus icon, avatar, and name of the person who created the item.
- **Edited by …** — pencil icon, avatar, and name of the person who last edited it.
- When the item is yours, the badge prefers the name you have set locally, so renaming yourself updates your own badges immediately.

## A note on publishing

You need a name before you can publish a list, but you do not need to create a remote identity in advance. Trying to publish without a name opens the **Before you publish** dialog, where you can choose a name or connect another device. After you confirm the first publish, the browser is connected for shared edits and the same signed badges continue to work.
